# Контрольные сценарии

Используй эти сценарии для проверки поведения навыка. Для каждого выполни запрос и сопоставь результат с ожидаемыми свойствами. Единственной правильной формулировки нет. Примеры не являются результатами выполненных тестов.

## Т01. Отрицание, число, срок и исключение

Запрос: «Строгий режим. Перепиши: Не удаляйте журналы в течение 30 дней, кроме временных журналов диагностики, которые разрешено удалять через 2 дня».

Ожидание: сохранены запрет, оба срока, объект исключения и разрешение, а не обязанность удаления. Не добавлено событие начала отсчета, которого нет в исходнике. Правила К01, К04, С05.

## Т02. Обязательность и неопределенность

Запрос: «Перепиши требование: Служба должна записывать код ошибки. Возможно, повторный запрос поможет. Рекомендуется проверить журнал».

Ожидание: обязанность, предположение и рекомендация остаются различными. Успех повторного запроса не гарантируется. Правила К04, С05.

## Т03. Неоднозначное местоимение

Запрос: «Упрости инструкцию: После подключения клиента к серверу перезапустите его».

Ожидание: вопрос о том, что перезапустить, либо явная отметка неразрешенной неоднозначности. Нельзя самостоятельно выбрать сервер или клиент. Правила К03, К05.

## Т04. Ошибка, сбой и отказ

Запрос: «Отредактируй отчет: В ответе неверная сумма. Затем соединение временно прервалось и восстановилось. После этого накопитель перестал выполнять чтение».

Ожидание: события не сводятся к одному диагнозу. Допустимо назвать неверную сумму ошибкой, временное нарушение с восстановлением — сбоем, потерю функции — отказом. Не добавлять причину, постоянство отказа или дефект реализации. Правила К02, К05.

## Т05. Терминология проекта

Запрос: «В нашем проекте «статус» — полный снимок всех свойств соединения, а «состояние» — значение enum. Упрости: Статус содержит параметры сеанса, состояние имеет значение READY».

Ожидание: определения проекта сохранены вопреки рабочему словарю навыка; READY не переведен и не переименован. Правила К02, К06.

## Т06. Последовательность

Запрос: «Разбей инструкцию на шаги: Сохраните файл, затем закройте редактор и после этого запустите сборку».

Ожидание: три действия в исходной последовательности. Не добавлены команды или условие успеха, отсутствующие в исходнике. Правила К01, С02.

## Т07. Одновременность

Запрос: «Проверь инструкцию в строгом режиме: Одновременно нажмите кнопки A и B».

Ожидание: одновременность сохранена. Допустимо трактовать это как одно составное действие. Если выделены два действия, оформить допустимое исключение С06 из С02. Последовательное нажатие недопустимо. Правила К01, С02, С06.

## Т08. Область действия условия

Запрос: «Строгий режим. Разбей на шаги: Если проверка завершилась успешно, сохраните отчет и отправьте его администратору».

Ожидание: оба действия остаются внутри общего условия. Нельзя сделать отправку безусловной после условного сохранения. Правила К01, К03, С02, С03.

## Т09. Длинное предложение

Запрос: «Упрости техническое описание: При получении запроса сервер проверяет подпись сообщения, определяет полномочия пользователя, загружает настройки проекта из локального хранилища, формирует результат обработки и возвращает клиенту ответ с кодом состояния и временем выполнения операции».

Ожидание: предложение разделено; сохранены событие, действия и содержимое ответа. Каждое новое предложение укладывается в С01. Порядок не изменен, атомарность и параллельность не добавлены. Правила К01, С01, С04.

## Т10. Обоснованное исключение длины

Запрос: «Проверь инструкцию. Точное название кнопки нельзя менять: Нажмите кнопку «Сохранить все выбранные пользователем параметры текущего проекта в отдельный файл для последующего восстановления на другом рабочем компьютере без изменения существующей конфигурации приложения и настроек подключенных служб»».

Ожидание: точное название сохранено. Длина требует исключения из С01, поскольку само название превышает предел. В аудите указаны С06 и С01, категория «Допустимое исключение» и причина. Правила К06, С01, С06.

## Т11. Команда, идентификатор и подстановка

Запрос: «Упрости: Осуществите запуск `npm run build -- --mode=production`. Значение поля user_id необходимо оставить неизменным. Сообщение «Не удалось загрузить {filename}» должно сохранять подстановку».

Ожидание: команда, user_id и {filename} сохранены точно; изменения исполняемого кода не предложены. Правило К06.

## Т12. Нейтральная переписка

Запрос: «Сделай нейтральнее: Привет! Спасибо за помощь. Если у тебя будет время, посмотри, пожалуйста, черновик. Я пока не уверен, что правильно описал причину».

Ожидание: сохранены обращение на «ты», благодарность, условная просьба и неуверенность. Не добавлены срок, обязанность, нумерация и технические заголовки. Допустимо оставить уже ясный текст почти без изменений. Правила К04, К05, Н01–Н03.

## Т13. Смешанный текст и явный режим

Запрос: «Отредактируй два фрагмента. Сообщение: Спасибо, что помог разобраться, теперь я лучше понимаю причину. Инструкция: Сохраните файл, затем закройте редактор».

Ожидание: сообщение остается нейтральным; инструкция получает отдельные шаги. При дополнительном указании «Весь текст в нейтральном режиме» автоматический строгий режим отменяется. Общее ядро сохраняется.

## Т14. Редактура и аудит

Вход: «Сохраните файл и закройте редактор».

Запрос А: «Перепиши в строгом режиме». Ожидание: только готовые шаги без таблицы нарушений.

Запрос Б: «Проверь в строгом режиме». Ожидание: исходный фрагмент, С02, категория «Структурное нарушение», объяснение и правка. Исходный файл не изменяется только из-за запроса проверки.

## Т15. Неоднозначная модальность

Запрос: «Проверь требование: Оператор может удалить архив».

Ожидание: вопрос о технической возможности или разрешении; не подменять исходник словом «должен». Если контекст отдельно указывает права доступа, допустимо сформулировать разрешение. Правила К04, К05, С05.

## Т16. Подсчет и границы текста

Запрос: «Проверь длину: Клиент-сервер использует retry_count=3 при задержке 0.5 с. Затем выполните команду `npm run build`».

Ожидание: первое предложение содержит 7 единиц, второе — 6. Точка в 0.5 не разделяет предложение, дефисное слово и идентификатор считаются по одному. Блок кода с тем же содержимым не проверяется по С01. Подсчет моделью не называется программной валидацией.
